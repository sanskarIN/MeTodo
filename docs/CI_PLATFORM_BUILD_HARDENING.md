# CI Platform Build Hardening

## Purpose

This document records the platform-build defects found during the MeTodo pull-request audit and the corresponding workflow corrections. The repository is an Expo SDK 54 managed application; its native Android and iOS projects are generated during CI and are not checked into source control. Desktop runners validate the Expo web distribution because this repository does not contain Electron build scripts or desktop packaging configuration.

## Android

The Android workflow now installs pnpm before enabling pnpm caching, generates the Android project with `npx expo prebuild --platform android --no-install`, and uses the NDK version generated by Expo SDK 54 (`27.1.12297006`). Gradle caching is intentionally not enabled before prebuild because no Gradle files exist in a clean checkout. Debug APK compilation is performed only after the generated project is available.

The workflow also requires the launcher assets referenced by `app.config.ts`. Missing `icon.png`, `splash-icon.png`, `favicon.png`, and `android-icon-foreground.png` previously caused Expo prebuild to fail before Gradle started. These assets are now tracked in the repository.

## iOS

The iOS workflow generates the project with `npx expo prebuild --platform ios --no-install`, installs CocoaPods, and then builds the CocoaPods-generated `MeTodo.xcworkspace` using the `MeTodo` scheme. The previous workflow attempted to enter an absent `ios` directory and referenced the unrelated lowercase `metodo.xcworkspace` and `metodo` names.

## Linux, macOS, and Windows

The project package manifest does not define `build:electron`, `dist`, `dist:dmg`, `dist:app`, or native desktop packaging scripts. The previous workflows called those nonexistent commands and Linux additionally requested unavailable Ubuntu packages such as `libgconf-2-4` and `snapcraft`. The repaired workflows run the supported production server bundle and export the Expo web distribution, upload that generated distribution as the platform validation artifact, and avoid claiming unsupported native desktop installers.

## Validation

The local application suite passes TypeScript compilation, Vitest, production server bundling, Expo lint, Expo web export, and whitespace checks. Both Android and iOS Expo prebuilds complete successfully after the launcher assets are restored. A full Android Gradle compile requires an Android SDK installation; on the sandbox, the observed failure was environmental because `ANDROID_HOME` and `ANDROID_SDK_ROOT` were unset. GitHub Actions installs the required SDK and NDK explicitly.

## Remaining repository-level requirements

The GitHub pull request still requires code-owner approval under the protected `main` policy. Hosted platform checks must complete on the repaired commit before merge. Dependency advisories reported by GitHub remain a separate security-maintenance workstream and should be handled through dedicated reviewed upgrades rather than mixed into platform-build fixes.
